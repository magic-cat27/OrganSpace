# 🧬 器域 OrganSpace — 空间数字人体病理仿真平台

> **器域 OrganSpace 是一个将三维器官空间、动态病理生理模型和多智能体教学解释相结合的数字人体仿真平台。**

基于 [Organ-Agents 论文](organ-agents.pdf) 的多智能体架构思想，面向医学教学与临床培训场景，动态展示疾病如何随时间发展并影响多个器官系统。

> 长期发展目标：在加入药物模型、个体差异和临床数据校准后，探索数字患者队列和药物机制前置验证。

---

## 🎯 核心创新点：混合多 Agent 架构 + 空间智能

```
疾病控制器（只注入原始扰动）
        ↓
统一状态仓库 BodyStateStore
        ↓
确定性器官 Agent 独立提出状态提案（肾脏 → 血液 → 心血管）
        ↓
调度器汇总 · 解决冲突 · 统一提交（不直接计算医学指标）
        ↓
生理校验器检查边界 · 触发风险警报
        ↓
前端指标卡 · 趋势曲线 · Agent 执行轨迹 · 3D 联动
```

### 数值层：确定性器官 Agent 协作（非集中式）

| 层 | 职责 | 实现 |
|---|---|---|
| **疾病控制器** | 只描述疾病起点与持续扰动 | `DiseaseController`（eGFR 目标等） |
| **器官 Agent** | 本器官的确定性响应，只写自己负责的状态（状态所有权） | `RenalPhysiologyAgent` / `BloodPhysiologyAgent` / `CardiovascularPhysiologyAgent` |
| **调度器** | 顺序、冲突解决、统一提交 | `PhysiologyEngine`（不再直接包含全部器官公式） |
| **生理校验器** | 数值边界 + 风险警报 | `_validate()` |
| **LLM 解释层** | 因果解释、教学问答、结果总结（不参与数值决策） | 主协调 Agent + 器官 Agent（LLM 模式） |

**状态所有权矩阵**（Agent 可读全局快照，但只写自己的状态）：

| Agent | 主要读取 | 主要写入 |
|---|---|---|
| 肾脏 Agent | 疾病扰动、当前肾功能 | eGFR、尿量、肾灌注 |
| 血液 Agent | 肾脏清除能力 | 肌酐、BUN、血钾、HCO₃⁻、pH、AG、渗透压 |
| 心血管 Agent | 血钾、MAP、交感信号 | 心率、心输出量、心律失常风险、MAP、交感信号 |

分阶段时间步：读快照 → 疾病扰动 → 器官 Agent 提案 → 调度汇总 → 统一提交 → 生理校验。

### 空间层：三维几何参与计算（非仅展示）

- **空间语义注册表**：GLB 加载后自动计算每个器官的包围盒、几何中心、尺寸、近似体积与主轴；
- **空间邻近图**：由几何自动计算最近邻（区别于人工定义的功能连接表 CONNECTIONS_3D）；
- **局部病灶影响场**：点击器官放置病灶球，按各器官到病灶的距离做衰减计算，红/橙/黄热力高亮 + 邻近器官列表（归一化空间距离，非临床测量值）；
- **空间合理性检查**（规划）：左右轴/高度区间/包围盒相交等自动校验。

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r backend/requirements.txt
```

### 2. 启动服务

```bash
cd backend
python server.py
```

服务默认运行在 **http://localhost:8765**（`HOST`/`PORT` 可用环境变量覆盖）。

### 3. 使用

浏览器打开 http://localhost:8765 即可。

> 💡 **推荐浏览器**：Chrome / Edge 最新版（完整支持 WebGL2、Import Maps 与 ES Modules）。

## 🔬 两种工作模式

### 模式一：疾病模拟（确定性器官 Agent + 调度器）⭐ 主 Demo

- **完全无需大模型 API Key**，纯本地确定性计算，结果可复现；
- 疾病控制器注入扰动 → 肾脏/血液/心血管三个确定性 Agent 分阶段提案 → 调度器统一提交；
- **Agent 执行轨迹面板**：每步展示各 Agent 读取与修改了什么、原因是什么（答辩可直接看到多 Agent 协作）；
- 支持指标卡、趋势曲线、风险警报、三维肾脏联动高亮、**治疗干预（紧急透析）**；
- 当前支持的疾病模板：**急性肾损伤（AKI）**，严重程度：轻度 / 中度 / 重度。

### 模式二：智能解释 / 因果链 / 器官问答（需要 API Key）

- 自由文本场景 → 主协调 Agent 生成器官因果链 → 分步讲解；
- 依赖外部大模型 API，结果具有随机性，需网络与有效 Key。

## 📖 演示流程（答辩主 Demo：重度急性肾损伤）

1. 启动服务后，浏览器打开 http://localhost:8765；
2. 点击 **「进入疾病模拟」**；
3. 疾病模板选择 **急性肾损伤**，严重程度选择 **重度**（默认选中）；
4. 点击 **「开始仿真」**，随后连续点击 **「+10 步」** 或 **「▶ 自动播放」**；
5. 观察指标变化：**eGFR 下降**、**肌酐 / 尿素氮 / 血钾升高**、**pH 与 HCO₃⁻ 下降**、**尿量减少**；
6. 触发风险警报：高钾血症（K⁺ ≥ 6.0）、代谢性酸中毒（pH ≤ 7.25）、肾衰竭（eGFR ≤ 15）；
7. 点击 **「🩸 执行紧急透析」**，观察血钾 / 肌酐 / 尿素氮回落、HCO₃⁻ 与 pH 改善的治疗响应；
8. 三维场景中肾脏随 eGFR 状态变色（正常→应激→受损→衰竭），曲线与器官状态实时同步。

> ⚠️ **免责声明**：本系统所有生理参数与治疗干预仅用于**教学机制演示**，**不构成临床治疗建议**。

## 🧪 测试

```bash
cd backend
python test_disease_engine.py      # 疾病引擎测试（无 LLM，纯确定性，8 项断言全过）
python test_integration.py         # LLM 集成测试（需有效 API Key，可选）
```

疾病引擎测试覆盖：推进时间步后 eGFR 下降、肌酐 / 血钾升高、尿量下降、重度触发高钾+酸中毒警报、治疗干预的「改善→维持→反弹」、**多 Agent 传播链与执行轨迹（肾→血→心血管）**、生理值边界校验。

> WebSocket 接口已做防御性加固：未知疾病 / 非法严重程度 / 非法时间步 / 超大步数等脏输入均返回错误而不中断连接，现场演示更稳。

## 🔧 环境变量

复制 `.env.example` 为 `.env` 后按需填写：

```env
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=your-api-key
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
HOST=0.0.0.0
PORT=8765
```

- **疾病模拟模式无需任何 API Key**；
- 智能解释 / 因果链 / 问答模式需要 `DEEPSEEK_API_KEY`（或切换 `anthropic` 并配置 `ANTHROPIC_API_KEY`）；
- `.env` 已被 `.gitignore` 忽略，**切勿将真实 Key 提交到仓库**。

## 🖥 离线部署（现场演示）

- 所有前端依赖（three.js、DRACO 解码器、Chart.js）已本地化至 `frontend/vendor/`，**不依赖任何外网 CDN**；
- WebSocket 使用**同源连接**（自动 `ws`/`wss` + 当前端口），部署到任意端口/协议均可工作；
- 现场演示前：先启动后端 → 打开页面并完成模型加载 → 完整测试至少三次 → 保留已加载的浏览器标签页，并准备 2–3 分钟离线录屏作为 Plan B。

## 🏗 系统架构

```
Aholo 生成/处理三维器官资产
        ↓
GLB 器官与骨骼模型
        ↓
Three.js 空间数字人体（位置 / 比例 / 连接 / 状态高亮 / 病灶影响场）
        ↓
BodyStateStore 统一人体状态（血液指标 / 器官指标 / 神经信号）
        ↓
疾病控制器（疾病 → 原始扰动，不计算指标）
        ↓
确定性器官 Agent（肾脏 → 血液 → 心血管，状态所有权提案）
        ↓
调度器（时间步积分 / 冲突解决 / 统一提交 / 干预）
        ↓
生理校验器（边界 / 风险警报）
        ↓
WebSocket 实时同步
        ↓
指标卡 · 趋势曲线 · Agent 执行轨迹 · 风险警报 · 3D 联动
```

LLM 与多智能体作为**独立解释层**：

```
场景与状态数据 → 主协调 Agent → 器官系统 Agent → 因果解释 · 教学问答 · 结果总结
```

## 教学用途声明

本项目为**医学教学与临床培训**用途设计，旨在缓解典型病例难以重复获取的问题，为未来数字患者与药物干预模拟提供技术基础。**不用于临床决策、药物疗效预测或临床试验替代。**
